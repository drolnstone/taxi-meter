WHAT CHANGED SINCE YOUR LIVE VERSION
- Vehicle tab (the driver's own, on their phone only): a daily vehicle check
  (Fine / Advisory / Defect on 28 items) and renewal dates for plate, badge,
  insurance, MOT, DVLA licence and meter test, with reminders 60, 30 and 7 days
  out and a question before a trip if one has run out. Nothing about the
  vehicle is sent to the sheet or the Log tab.
- Each check can be saved or printed as a PDF ("Save as PDF").
- Settings → Vehicle check and reminders: On / Off, the driver's choice.
- Receipts can be saved as a PDF; Earnings has an earnings statement PDF for
  this/last week, this/last month or the tax year to date.
- Settings shows "App 1.10.0 · Sheet 1.2.0" after Test connection.
- Vehicle registration on every trip. The driver enters it once on the Meter
  tab (it is remembered), and Start trip asks for it if it is blank. It goes to
  a new "Vehicle Reg" column at the end of Trips (added by the first sync, nothing to
  do by hand), and onto the receipt, the PDFs and the CSV.
- Sheet columns are found by their heading, never by position (the minibus
  sheet's rule). Trips, Drivers, Log and the Summary formulas all follow the
  headings, so columns can be moved, inserted or added. Only renaming a
  heading matters. "Fix headers" is now "Add missing headers": it adds a
  missing heading at the end and never relabels or moves one.
- Sheet protection, ported from the minibus sheet: Trips, Log and Summary are
  locked warning-only (an edit asks you to confirm first), the Drivers heading
  row is locked, and it relocks itself every night at about 3am. Menu:
  Taxi Meter → Protect the sheet / Unprotect the sheet. The security check
  names any tab left unprotected.

DEPLOY
1. Paste Code.gs into the Apps Script editor, save, then
   Deploy → Manage deployments → edit → New version.
2. In the editor, run lockSheet once and accept the prompts. It asks for one
   new permission (to set the nightly relock timer).
3. Reload the spreadsheet, then Taxi Meter → Build or rebuild Summary tab, so
   its formulas are made from the headings.
4. Publish index.html, sw.js, vehicle.js, pdf.js and the vendor/ folder to the
   same folder as before.

GOING LIVE ON MERGE (set up once, then merging a PR is the deploy)

The app (GitHub Pages)
1. GitHub → drolnstone/taxi-meter → Settings → Pages → Source: Deploy from a
   branch → main, / (root) → Save. The app is then at
   https://drolnstone.github.io/taxi-meter/ and every merge republishes it.
   If drivers already use another address, keep it or move them over once:
   the phone's saved trips stay with the old address until synced.

Code.gs (GitHub Actions, .github/workflows/apps-script.yml)
1. https://script.google.com/home/usersettings → Google Apps Script API: On.
2. On a computer with Node: npm install -g @google/clasp@2.4.2, then
   clasp login, and sign in with the Google account that owns the sheet.
   It writes .clasprc.json in your home folder.
3. Apps Script → Project Settings → copy the Script ID.
4. The Deployment ID is the part of SYNC_URL in index.html between /s/ and
   /exec (starts AKfycb). Or: Deploy → Manage deployments → the web app.
5. GitHub → drolnstone/taxi-meter → Settings → Secrets and variables →
   Actions → New repository secret, three times:
   CLASPRC_JSON (the whole of .clasprc.json), SCRIPT_ID, DEPLOYMENT_ID.
6. Actions → Apps Script → Run workflow. It ends with "Code.gs 1.2.0 is
   live", or "already live".

Still by hand: anything that asks for a new Google permission (like running
lockSheet the first time) and menu actions such as rebuilding the Summary tab.
